# Horizon

Ротная система учёта мест и имущества (ТЗ v2.1).

Один человек — одно место. Строка остатка обновляется за секунды, красное не прячется, протухшие данные видны на «Панели».

```
web (React) ─► nginx ─► api (Fastify) ─► PostgreSQL 16 (RLS + функции)
```

| Каталог | Что внутри |
|---|---|
| `db/migrations` | Схема, функции раздела 9, RLS. Здесь живёт инвариант `UNIQUE (user_id) WHERE date_to IS NULL` |
| `server` | API, миграции, CLI; тесты |
| `web` | Клиент: React + TypeScript + Vite, TanStack Router/Query, Tailwind |
| `docker` | Dockerfile-ы, nginx, Caddy (HTTPS), бэкап |

## Запуск (`up`)

Нужен VPS с Docker.

```bash
cp .env.example .env
# заполните три пароля к БД и APP_SECRET: openssl rand -hex 24
docker compose up -d --build
```

Порядок запуска: `db` → `migrate` (накатывает схему и задаёт пароли ролей) → `api`, `backup` → `web`.
Веб слушает `127.0.0.1:8080`.

**HTTPS в бою.** Укажите в `.env` `DOMAIN`, `COMPOSE_PROFILES=tls` и `TRUST_PROXY_HOPS=2`, откройте порты 80 и 443 и запустите:

```bash
docker compose up -d
```

Профиль задаётся именно через `COMPOSE_PROFILES`, а не флагом `--profile`: по этой переменной API сверяет число прокси и с `tls` при `TRUST_PROXY_HOPS` меньше 2 не стартует (см. «Безопасность»).

Caddy сам получит сертификат. Cookie помечены `Secure`, поэтому для локальной проверки по http поставьте `SECURE_COOKIES=false`.

## Первый админ

```bash
docker compose run --rm migrate node dist/cli.js create-admin grom Гром
```

Команда выведет одноразовый код. Первый аргумент — логин для входа (латиница), второй — позывной.
CLI ходит в базу владельцем схемы, поэтому запускается в сервисе `migrate`: у `api` пароля
суперпользователя нет и быть не должно.

Откройте сайт, введите логин и код, отсканируйте QR приложением с одноразовыми кодами (Google Authenticator, Aegis, 1Password), задайте пароль и введите код из приложения. Код приглашения после этого сгорает.

## Пригласить человека

**Люди → «+ Человек»**. Введите логин (латиницей, им человек входит) и позывной (не фамилию). Код входа показывается один раз и действует 72 ч.
Человек входит по коду, подключает приложение с одноразовыми кодами, задаёт пароль и видит экран «Ожидайте назначения». Списка мест у него нет.

## Посадить

**Люди → человек → «Посадить»**. Выберите место и дату захода. Через 10 секунд у человека вместо экрана ожидания откроется таблица этого места.

Если у человека уже есть место, посадка не пройдёт с ошибкой «сначала переведите или снимите». Это правило держит уникальный индекс в БД, поэтому его нельзя обойти даже прямым запросом в базу.

## Перевести и снять

- **«Перевести»** — новое место и дата. Одной транзакцией старая привязка закрывается этой датой, а новая открывается той же датой. Человек пропадает из шапки старого места и появляется в шапке нового.
- **«Снять»** — закрывает привязку без новой. Человек снова видит экран ожидания.

Историю мест не удаляют: она видна в карточке человека.

Админ зоны может сажать и переводить людей только в пределах своих мест. Для перевода ему нужны права и на текущее место человека, и на новое.

## Таблица и цвет

Для каждой строки задаются три порога: мин / приемлемо / идеал. Правило: `мин ≥ 0` и `мин < приемлемо ≤ идеал`. Пороги вида 50/20/100 не сохранятся.

| Остаток | Цвет |
|---|---|
| `< мин` | 🔴 красная, всегда вверху и не скрывается фильтрами |
| `< приемлемо` | 🟡 жёлтая |
| `≥ приемлемо` | 🟢 зелёная |
| `≥ идеал` | 🟢 + метка «полн» |

Как быстро обновить строку: нажмите на остаток, введите число, нажмите Enter. Сохранение с тем же числом тоже считается обновлением: так подтверждают, что остаток проверен.
Последнее изменение количества («было → стало», кто и когда) хранится в `stock_movements` и видно в карточке строки. Полной истории движений нет: на каждую строку хранится одна запись, и следующая правка её перезаписывает.

Кнопки «−/+» отправляют не только новое число, но и то, от которого считали. Если за это время остаток поменяли с другого телефона, сохранение не пройдёт: появится сообщение с текущим числом, и правку нужно повторить от него. Так две одновременные правки не затирают друг друга.

## Языки

Украинский (`uk`, основной) и английский (`en`). Язык выбирают в шапке или на экране входа. Выбор сохраняется в профиле.

Чтобы добавить язык (например, `pl`):

1. Создайте `web/src/locales/pl.ts` по образцу `en.ts`. TypeScript не пропустит словарь, в котором не хватает ключей.
2. Добавьте строку в `LANGUAGES` в `web/src/i18n.tsx`.
3. Добавьте код `pl` в `LOCALES` в `server/src/i18n.ts` — сервер принимает только языки из этого списка.

Миграция не нужна: база принимает любой двухбуквенный код, а список допустимых языков задаёт сервер.

## Бэкап

Контейнер `backup` каждый день в `BACKUP_AT` делает `pg_dump` в `./backups` и хранит дампы `BACKUP_KEEP_DAYS` дней.

```bash
docker compose exec backup /bin/sh /backup.sh now      # снять дамп сейчас
```

Восстановление:

```bash
docker compose stop api
docker compose exec -T db pg_restore -U postgres -d horizon --clean --if-exists < backups/horizon-YYYYMMDD-HHMMSS.dump
docker compose start api
```

Задайте `BACKUP_PASSPHRASE` — дампы будут шифроваться (AES-256, PBKDF2), файл получит расширение `.dump.enc`. В дампе хеши паролей и секреты приложения, поэтому за пределы сервера копию выносят только шифрованной, а пароль хранят отдельно от дампов.

```bash
openssl enc -d -aes-256-cbc -pbkdf2 -in backups/horizon-....dump.enc -out restore.dump -pass env:BACKUP_PASSPHRASE
```

Копируйте `./backups` за пределы сервера.

Дамп, который ни разу не восстанавливали, — это не бэкап, а предположение. Проверить:

```bash
./scripts/restore-check.sh backups/horizon-YYYYMMDD-HHMMSS.dump
./scripts/restore-check.sh backups/horizon-YYYYMMDD-HHMMSS.dump --migrate   # репетиция выкладки
```

Скрипт поднимает одноразовый Postgres, разворачивает в него дамп и проверяет инварианты: ни у кого не больше одной открытой привязки, пороги в правиле, полный админ на месте, наружу не торчат функции схемы. Наружу печатаются только числа — личный состав в лог проверки не попадает. С `--migrate` поверх копии боевых данных прогоняются непринятые миграции: это репетиция выкладки, а не проверка на пустой базе, где ломается далеко не всё.

## Наблюдение

Своего мониторинга нет и не нужно: хватает внешнего пингера. Письмо о том, что сервер лёг, не может отправить лёгший сервер, поэтому наблюдатель обязан быть снаружи.

`/api/health` открыт без входа и отдаёт всем ровно два слова:

```json
{ "ok": true, "degraded": false }
```

`degraded` поднимается, если за последний час была хоть одна пятисотка или больше десяти отказов по частоте. Первое — ошибка в коде или в базе, второе — либо неверный `TRUST_PROXY_HOPS`, либо перебор паролей. И то и другое требует человека.

**UptimeRobot, две проверки:**

| Тип | Адрес | Интервал | Условие тревоги |
|---|---|---|---|
| HTTP(s) · Keyword | `https://<домен>/api/health` | 5 мин | ключевое слово `"degraded":false` **отсутствует** в ответе |
| Heartbeat | ссылку вписать в `BACKUP_PING_URL` | 26 часов | сигнал не пришёл |

Первая ловит всё, что ловит человек с позиции: упавший контейнер, мёртвый VPS, протухший сертификат, сломанный DNS, — и вдобавок `degraded`. Вторая — единственное, что внешней проверкой не увидеть: бэкап перестал сниматься, а сайт при этом прекрасно работает. Если в вашем тарифе heartbeat-проверки нет, для неё подойдёт любой бесплатный сервис «мёртвого выключателя», `BACKUP_PING_URL` к конкретному не привязан.

Подробности — только по токену:

```bash
curl -H "x-horizon-ops: $OPS_TOKEN" https://<домен>/api/health
# {"ok":true,"degraded":false,"migrations":17,"schema":"017_cleanup_health.sql","errors":0,"throttled":0}
```

`schema` полезен сразу после выкладки: он показывает, доехали ли миграции, или образ поднялся на старой базе.

## Потерян доступ

- **Люди → человек → «Сбросить сессии»** — все входы человека закрываются, при следующем входе он вводит пароль и код из приложения заново.
- **«Новый код входа»** — дополнительно стирает пароль и привязку приложения и выдаёт новый одноразовый код. Используйте, если устройство могло попасть в чужие руки: без этого у нашедшего остаётся генератор кодов.

Если доступ потерял единственный полный админ:

```bash
docker compose run --rm migrate node dist/cli.js reset-access grom
```

## Безопасность

- Логин нужен только для входа, в таблицах его не показывают. В интерфейсе только позывные. Ни координат, ни телефонов, ни ФИО в базе нет.
- Вход: логин, пароль и одноразовый код из приложения (TOTP, RFC 6238). Внешние сервисы не участвуют, коды считаются без интернета.
- Пароль хранится как scrypt-хеш: минимум 8 символов, у админа — 12, очевидные и словарные отклоняются.
- Подбор тормозят лимиты (`horizon.auth_gate`): на пару «IP + логин» задержка растёт 1, 2, 4 … 60 секунд, с одного IP не больше `LOGIN_FAILS_PER_IP_HOUR` неудач в час, на один логин со всех адресов — не больше `LOGIN_FAILS_PER_USER_HOUR`. Последний лимит не действует на устройство, с которого человек уже входил: чужие ошибки не держат владельца снаружи. С одного IP одновременно идут не больше трёх попыток входа.
- Одновременных вычислений scrypt не больше `PASSWORD_HASH_CONCURRENCY`, и считаются они без соединения с базой: вход нельзя превратить в нагрузку на сервер или в очередь к пулу.
- Одноразовые коды входа хранятся как HMAC на ключе из `APP_SECRET`: по одному дампу базы их не подобрать.
- API доверяет `X-Forwarded-For` ровно на `TRUST_PROXY_HOPS` прыжков. Число обязано совпадать с реальной цепочкой: только nginx — **1**, профиль `tls` (Caddy → nginx → api) — **2**. С заниженным числом адресом каждого клиента станет адрес прокси, и 20 чужих ошибок входа в час закроют вход всей роте. С завышенным API поверит адресу, который прислал сам клиент, и лимит обойдут подстановкой заголовка. С `COMPOSE_PROFILES=tls` и числом меньше 2 API не стартует.
- Секрет приложения лежит в базе зашифрованным (AES-256-GCM, ключ `APP_SECRET`): одного дампа базы мало, чтобы получать коды.
- Один код действует один раз: использованный 30-секундный интервал запоминается.
- Сессия — случайный токен в httpOnly-cookie с `SameSite=Strict` (на HTTPS с префиксом `__Host-`). В БД хранится только его хеш.
- Сессия привязана к устройству и раз в `SESSION_ROTATE_HOURS` меняет токен. Если ответ с новым токеном потерялся (обрыв связи), сервер выдаст его заново при следующем запросе со старым. Если же новым токеном уже пользовались, а старый всплыл снова, это считается кражей: все сессии человека гаснут, событие попадает в `audit_log`.
- Защита от CSRF: каждый POST должен нести заголовок `X-Horizon`.
- API подключается к БД ролью `horizon_api`. Для запросов человека она переключается в `horizon_user`, а та только читает, и то в пределах RLS. Все записи идут через функции с явной проверкой прав.
- Нельзя снять права с последнего полного админа.

**Политику «один человек — одно место» не ослаблять «на время» без новой версии ТЗ.**

## Разработка

```bash
npm install
npm test               # тесты БД и API на встроенном Postgres (PGlite), Docker не нужен
npm run typecheck
docker compose up -d db
npm run migrate -w server       # с DATABASE_ADMIN_URL=postgres://postgres:<пароль>@localhost:5432/horizon
npm run dev:api                 # :3000
npm run dev:web                 # :5173, проксирует /api
```

Если БД в Docker, опубликуйте порт `db` (добавьте `ports: ['127.0.0.1:5432:5432']` в override-файл).

Тесты покрывают критерии приёмки раздела 13:

- посадка;
- запрет второй посадки;
- уникальный индекс при прямом INSERT;
- перевод и снятие;
- цвета 18/35/80;
- отказ для порогов 50/20/100;
- revoke;
- права админа зоны;
- вход с нового устройства;
- справочник категорий.

## Деплой

### Первый раз

На сервере (Ubuntu, открыты порты 80 и 443, домен смотрит A-записью на его адрес):

```bash
curl -fsSL https://get.docker.com | sh
mkdir -p /opt/horizon
```

С рабочей машины — код и настройки:

```bash
git archive --format=tar HEAD | ssh user@host 'tar -x -C /opt/horizon'
scp .env.prod user@host:/opt/horizon/.env      # заполненный по .env.example
```

В `.env` обязательны `POSTGRES_PASSWORD`, `HORIZON_API_DB_PASSWORD`, `APP_SECRET`, `DOMAIN`.
`COMPOSE_PROFILES=tls` поднимает Caddy, он сам выпустит сертификат. Пароли — только
латиница и цифры: они подставляются в строку подключения.

Дальше на сервере:

```bash
cd /opt/horizon
docker compose up -d --build
docker compose run --rm migrate node dist/cli.js create-admin grom Грім
```

Последняя команда напечатает одноразовый код. Откройте `https://<домен>`, войдите по
нему, задайте пароль и подключите приложение с одноразовыми кодами.

### Обновления

```bash
PROD=user@host ./scripts/deploy.sh
```

Скрипт по порядку: тесты → бэкап боевой базы → выкладка → проверка `/api/health`.
С промежуточным сервером — `STAGING=user@stage PROD=user@host ./scripts/deploy.sh`.

CI — `.github/workflows/ci.yml`.
